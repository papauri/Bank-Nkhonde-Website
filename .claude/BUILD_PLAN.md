# ⚠ ARCHITECTURAL PIVOT — decided by the user, cycle 3

**The project is migrating OFF Firebase ONTO PHP + MySQL.** This supersedes the stack section above.

- **Runtime:** PHP + MySQL (a real server process — the static-hosting model is being abandoned).
- **Sequencing:** *Scaffold first, migrate incrementally.* Build the SQL schema, `.env`, and DB connection **alongside** Firebase. Port one feature at a time (auth → groups → loans → payments). **The app keeps working throughout.** Firebase code is deleted only at the very end, once nothing imports it — and only with explicit human sign-off.
- **Local DB:** none yet. The user will stand up MySQL later. This cycle produces **migration files only** — nothing is executed against a live database.

**Why this is not a swap of the data layer:** a browser cannot talk to SQL. Firestore was queryable from client JS because `firestore.rules` enforced auth. MySQL has no equivalent, so every one of the 55 scripts that calls Firestore directly must become a `fetch()` against a PHP endpoint that we write, and `firestore.rules` must be re-implemented as server-side middleware. Auth, storage, and authorization all become ours.

**Implications for the work already done:**
- The cycle-2 hardening of `functions/index.js` is thrown away when Cloud Functions go. It only has value if you deploy it before the migration lands.
- **B2 (rotate the SMTP password) stands regardless of stack.** The credential is compromised and in `git log`. SQL does not change that.
- Firebase items below (BLOCKER-1, BLOCKER-3, firestore.rules reconciliation, indexes) are **PARKED**, not done — they matter only if the migration is abandoned.

### Bugs found and fixed

2. **`loanPenaltyType`/`contributionPenaltyType` were not in `rules.update`'s whitelist at all, and the schema default (`'percentage'`) is a mode the penalty engine never implemented** (`api/lib/penalty.php` and the inline contribution-penalty logic in `api/handlers/payments.php` both throw/501 on `'percentage'`, only `'fixed'` is real). ### App-wide latent bug found and fixed (via ui-designer, during dashboard polish)

4. **Colored toasts (`success`/`warning`/`danger`/`info`) have silently rendered as plain grey app-wide since the app was built.** `showToast(msg, type)` sets `className = "toast toast-${type}"` (hyphenated), but `design-system.css` and `admin-layout.css` had color rules written as `.toast.danger` etc. (space-separated, no hyphen) — a selector that never matched. Fixed: renamed the CSS selectors to match what the JS actually emits (`.toast.toast-success`, `.toast.toast-danger`, etc.) in both files. **One remaining occurrence of the old broken pattern in `styles/mobile-design-system.css` — confirmed dead/unloaded by any live page, not fixed (out of scope, zero live impact).** QA PASS.
